- **2026-08-24** — Migrations in `packages/supabase/migrations/` are never auto-applied (no CI/deploy hook). One sat unapplied and silently did nothing (an AppData row + a Switch in the UI that read it) until run manually via the Supabase Management API with `SUPABASE_ACCESS_TOKEN`, since no DB password was available for `supabase db push`. Full how-to: `docs/SUPABASE.md`.
- **2026-08-24** — `AppData` RLS is `authenticated`-only by default (one blanket policy). A public/unauthenticated page (e.g. `/menu`) reading it via the anon key silently gets `[]` — looks correctly wired in the frontend but never actually works for real customers. Needed a narrowly-scoped `anon` SELECT policy for just the one key that had to be public (table also holds `server_ip`/`server_port`, which must stay private). Full how-to: `docs/SUPABASE.md`.
- **2026-08-24** — `pnpm dev` binds port 3000 by default (`vite.config.ts`), but on this Mac port 3000 is held by an unrelated local project, and port 3001/3002 etc. get taken by any other concurrently-running `pnpm dev` for _this_ project (e.g. two agent sessions each running their own dev server) — Vite silently falls through to the next free port and prints the real URL in its own startup log. Don't assume `localhost:3000` when testing, and don't assume there's only one dev server instance running; read the actual `Local:` line, and check `lsof -i :<port>` if unsure.
- **2026-08-24** — `TABLE_NUMBERS` (was a static `Array.from({length: 30}, ...)` in `data/data.tsx`) has been replaced by `getTableNumbers(appData)` in `useAppData.tsx`, driven by the `table_count` AppData key (admin-editable on the Tisch-QR-Codes settings page, `pages/Settings/TableQrCodes.tsx` — moved there from Organisation settings since it's menu/table config, not org info). Any future code needing "all table numbers" should call `getTableNumbers(appData)`, not hardcode a range.
- **2026-08-24** — `useUpdateAppData` only does `.update().eq('key', key)` — no upsert. If the row doesn't exist yet (e.g. a just-added AppData key whose seed migration hasn't been pushed to the live DB), the update silently matches zero rows and still fires `onSuccess`/shows the success toast, even though nothing was saved. Always ship a seed migration (`INSERT ... WHERE NOT EXISTS`) alongside any new AppData key, and push it (see `docs/SUPABASE.md`) before relying on the settings UI for that key.
- **2026-08-24** — An admin settings input bound to an AppData value (e.g. Tisch-QR-Codes' "Anzahl Tische") writes on `onBlur`, not on an explicit save action. If two browser tabs/sessions have the same settings page open, the one with stale local state can silently overwrite a value the other tab just saved, whenever its input loses focus (tab switch, dev-server HMR reload, etc.) — observed `table_count` flip from a just-saved `26` back to the default `30` this way. Not a code bug per se, but worth checking for multiple open tabs before concluding a save "isn't sticking".
- **2026-08-24** — The app shell (`components/Navigation.tsx`) wraps routed content in `max-h-screen` + `overflow-y-auto` for the scrolling admin layout. Printing (`window.print()`) an overflow-auto container only prints the visible viewport-height slice, not the full scrollable content — this silently truncated the Tisch-QR-Codes print output. Fixed with `print:max-h-none print:overflow-visible` on that wrapper; any future page relying on `window.print()` benefits from this fix automatically, but keep it in mind if the wrapper is ever restructured.
- **2026-08-24** — Replaced the `qrcode.react` dependency with `qr-code-styling` (canvas/SVG QR codes with rounded dots, gradients, and a center logo/image, plus `getRawData()` to export PNG) for the café-branded Tisch-QR-Codes page (`pages/Settings/TableQrCodes.tsx` + `tableQrCodeStyle.ts`) — it was the only place using `qrcode.react`, so that dependency was removed rather than kept alongside.
